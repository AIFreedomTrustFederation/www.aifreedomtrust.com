This repository is the public doorway, not the central brain of the Federation. Its job is to make the whole system legible to someone arriving from outside: what the Federation believes, which projects exist, what each project actually owns, which claims are conceptual or empirical, where applied systems prove the model in ordinary work, and where a reader or collaborator should go next.

## Book I — The Doorway Must Tell the Truth

A public portal creates the first relationship between the Federation and a reader. That relationship should begin with clarity rather than spectacle. The site may express the larger vision in beautiful language, but it must not collapse distinctions that the repositories themselves preserve.

A doctrine paper is not a deployed service. A reproducible research package is not universal proof of every Federation claim. A prototype is not a production network. A public interface is not audited custody. A business storefront remains a business storefront even when Federation infrastructure works behind it. A project may carry sacred, philosophical, symbolic, or visionary language while its engineering and operational claims remain tied to code, tests, deployments, records, and evidence.

## Book III — SOP-ALOHA-001 at the Public Boundary

The shared loop becomes a publishing and navigation discipline:

```text
Receive → Inspect → Name → Propose → Consent → Act → Verify → Record → Return
```

**Receive** begins with a public statement, project link, new repository, release, research result, deployment, business surface, or mission-facing change. **Inspect** checks the actual repository metadata, code, document, URL, and evidence before the portal describes it. **Name** assigns the correct layer and project role rather than using generic language. **Propose** may improve public explanation without changing a project's underlying authority. **Consent** applies to public claims, publication of sensitive information, or representations that materially affect identity, rights, finance, safety, customer trust, or reputation. **Act** updates the static public surface. **Verify** confirms that HTML, CSS, assets, links, and live Pages routes work. **Record** preserves the public change in Git. **Return** gives the reader a reliable path to the actual project source.

No dependency installation is required. A local preview can be started with:

```bash
python -m http.server 4178 --bind 127.0.0.1
```

Then open:

```text
http://127.0.0.1:4178/
```

Verification should confirm that `index.html`, `styles.css`, `assets/aift-federation-hero.png`, documentation links, and the live GitHub Pages route resolve as expected. Project status and security boundaries live in `docs/status.md`, `docs/validation.md`, and `docs/security-and-privacy.md`.

The portal should never become a second, stale copy of every repository. Its task is orientation. It speaks in the same Federation voice, explains the same covenant, and gives enough context for the reader to understand how the parts fit together. Then it returns the reader to the project that owns the next level of detail.

The live portal is published through GitHub Pages at <https://aifreedomtrustfederation.github.io/www.aifreedomtrust.com/>.
